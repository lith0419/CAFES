# Scan-Path Continuity Diagnostics

## Scope

Single-point correlation diagnostics determine an initial method route from
orbital, occupation, gap, amplitude, and solver-stress evidence. They cannot
determine whether results produced by different methods form a physically
continuous scan. Scan-path continuity diagnostics address that separate
question only when the user explicitly requests `Analyze Results` after final
case results have been merged. `Run Plan` does not inspect neighboring cases or
reuse their density matrices; its task calculations remain independent.

For block2 studies, `Analyze Results` also performs a separate low-energy-state
continuity pass before proposing MPS continuation. It tracks root identity, not
only the smoothness of the ground-state energy curve.

## Detection Rule

The current implementation applies only to completed one-dimensional scans
with at least four successful energy points. It:

1. selects the sole varying numeric case variable and final energy when
   available;
2. finds adjacent points whose executed methods differ and checks each
   one-sided scan endpoint separately;
3. compares an internal boundary slope or endpoint slope with nearby slopes; and
4. requires both a large relative slope mismatch and a finite energy residual
   before requesting review.

Internal anomalies still require a method transition. An endpoint anomaly is
reported only as a continuity risk: a steep edge may be real short-range
repulsion or other physical behavior, so it triggers bidirectional validation
rather than immediate method promotion. This is a routing-quality diagnostic,
not a phase boundary or a replacement for molecular correlation diagnostics.

## Refinement Policy

For a flagged molecular transition or endpoint, the planner first constructs a
local window. The left branch executes targets in ascending coordinate order;
the right branch executes them in descending order. The first task uses a
compatible external anchor. At a physical scan endpoint, the outward branch
uses the original endpoint 1RDM as its baseline seed. Every later task uses the
new `one_particle_state` artifact produced by the immediately preceding task in
that branch. This is genuine adjacent-task continuation rather than restarting
every target from one fixed anchor.

Compatibility requires the same element ordering, basis, charge, spin, and
restricted/unrestricted policy. The target method is unchanged; the
transferred state is the source task's converged SCF-reference density, not its
correlated wavefunction. Same-method/reference internal continuation may be
tried automatically. Explicit `pyscf-agent.path-restart-approval.v1` review is
required for cross-method/reference reuse and for endpoint validation. Each
approval item identifies concrete seed artifacts by filename and recorded provenance and
marks interior sources as deferred artifacts generated by the preceding
approved branch task.

The source density is a converged SCF reference 1RDM, saved as a binary
`one_particle_state` artifact with recorded provenance. Its numerical array is never
sent to the LLM or included in compact workflow context. The two branches must
both converge and agree in final energy; reference energy, spin expectation,
and SCF stability are additional checks when present. Only a validated pair
may replace the point used for continuity analysis. The original `TaskReport`,
and both branch reports, remain linked in the merged report.

If two compatible anchors cannot be built, the branches disagree, or the
merged path remains anomalous, the planner constructs a local
`path-refinement` CASSCF plan for both sides of the overlap window. It uses a
shared valid CAS size and electron count, with geometry-specific orbital
indices recorded in each ActiveSpaceAudit. Those candidates are reviewed
together because they belong to one executable continuity-refinement plan; the
user may approve or edit them before the subset run. The planner never silently
replaces already successful points.

The rerun merges into the full study report before plots or subsequent analysis
are trusted. Current model-Hamiltonian scans receive the diagnostic summary but
do not yet construct an automatic path-refinement solver plan.

## DMRG State Continuity

Explicit molecular DMRG-CASSCF continuation can transfer a joint orbital/MPS
checkpoint between nearby geometries using
`solver.options.restart_geometry_policy="transport"` and `restart_manifest`.
The default remains `same_geometry`. Transport requires the same atoms/basis,
charge/spin, CAS/core/frozen partitions, roots and state-average weights. The
projected orbital blocks are aligned to source labels and phases; saved MPS
site order is pinned. `restart_min_active_overlap` (default 0.9) bounds the
smallest active cross-overlap singular value. Incompatibility fails explicitly.
This is an approximate MPS initial guess in transported orbitals, not an exact
wavefunction transformation or automatic root tracking. Target integrals and
all roots are recomputed. `target_scf_core` requires fresh MPS and cannot be
combined with this policy. The solver's first-call restart evidence establishes
whether MPS loading actually occurred. A deferred Study `restart_manifest`
reference names `source_case_id` and `artifact_kind=block2_mps_manifest`; such
dependent cases execute sequentially and retain parent Run provenance.

For ordered molecular or finite-model block2 cases with targeted roots, compare
root signatures in the same particle/spin/symmetry sector. Root 1RDM overlap is
the preferred evidence; natural-occupation similarity is the fallback and
excitation energy is secondary. The assignment may preserve root order, detect
a reorder, or mark the link ambiguous. Ambiguous cases remain visible in the
study report and are excluded as MPS continuation anchors.

This analysis is not run during the initial independent tasks. It is attached
as `adaptive-dmrg-state-tracking.json` only after explicit result analysis, then
feeds the reviewable same-method MPS retry. Transition RDMs and direct MPS
wavefunction overlaps are not currently available, so weak assignments must not
be presented as exact state labels.

## Artifacts And State

- `scan-path-diagnostics`: versioned transition metrics, flagged cases, and
  local method recommendation.
- `one_particle_state`: registered binary AO reference 1RDM from a
  converged molecular SCF calculation.
- `adaptive-path-window-restart-plan`: paired left/right ordered subset plans
  carrying concrete seed artifacts and deferred adjacent-case references.
- `adaptive-path-window-restart-validation`: comparison of both restart
  branches and its explicit acceptance decision.
- `path-restart-approval`: a fingerprinted review contract for endpoint
  validation or cross-method/reference SCF 1RDM reuse.
- `adaptive-path-refinement-plan`: shared-CAS CASSCF plan for an overlap window
  that remains anomalous or cannot establish a unique continuation branch.
- `path_refinement_review_required`: workflow state for the local
  ActiveSpaceAudit batch.
- `adaptive-dmrg-state-tracking`: cross-case root mapping, evidence,
  confidence, reordered roots, and ambiguous case ids.

## Failure Cases

- Using an individual strong-correlation score to assert that a method stitch
  is smooth.
- Passing a density between incompatible geometries, basis sets, spin states,
  or reference policies.
- Launching a cross-method/reference continuation without showing both anchors
  and obtaining plan-scoped approval.
- Treating a steep endpoint as a method failure without checking both
  propagation directions.
- Reusing one fixed anchor for every point while presenting the operation as a
  directional scan.
- Replacing a point after a single successful continuation branch.
- Replacing a completed scan with only the local refinement report.
- Filling a missing high-level energy with an MP2 value when plotting a final
  curve.
